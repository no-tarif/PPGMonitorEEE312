# PPG Monitor

An Android app that turns raw PPG (photoplethysmography) and accelerometer
data into a live heart-rate and SpO2 reading — from a real ESP32 sensor rig
(`HARDWARE_SETUP_GUIDE.md` in the course folder), a bundled recorded
dataset, or a CSV / Excel file you pick on the phone.

## What it does

- **Live waveform + heart rate.** Streams raw `ir`/`red`/accelerometer
  samples through a DSP pipeline (band-pass filter → running
  normalization → accelerometer-referenced LMS motion-artifact removal →
  windowed FFT heart-rate estimation) and shows the cleaned PPG waveform,
  current BPM, and a signal-quality index (SQI) on screen in real time.
- **Interchangeable sample sources**, selectable from the main
  screen (the old Simulated source was removed in v3; readings recorded
  with it still open):
  - **Dataset** — replay of a bundled, pre-recorded CSV dataset (with
    1x/2x/4x/Fast playback speed and optional looping), including a
    ground-truth reference BPM overlay where the dataset provides one.
  - **ESP32 (USB)** — a real sensor rig connected over wired USB serial
    (phone as USB host). This is the only source tested against real
    hardware so far.
  - **ESP32 (BLE)** — a Bluetooth LE path to the same kind of rig, kept in
    the codebase as a fallback/alternative but not yet exercised against
    real firmware.
- **Session recording and history.** Every Start-to-Stop session is
  recorded automatically (regardless of which source was active) into a
  local Room database, as long as it runs at least 15 seconds. A History
  screen lists past sessions and lets you drill into one to review its
  readings.

## Scope

This is a **v1: PPG waveform + heart rate only**. The sensor data model
already carries both `ir` and `red` channels and raw accelerometer axes
per sample, so later work like **SpO2** (needs red+ir from the same
instant) or **hemoglobin estimation** (needs additional wavelengths not
yet supported by the hardware) can be added by extending the pipeline,
without changing the sensor layer or reworking the app's structure.

Explicitly out of scope for now:
- SpO2 / hemoglobin estimation
- BLE firmware integration testing (structurally implemented, unverified)
- Any GPS/location use — location permission is only requested because
  older Android versions require it for BLE scanning, not because the app
  uses location

## Architecture overview

- `model/SensorSample` — one timestamped raw reading (`ir`, `red`,
  `accX/Y/Z`), the common currency between every sensor source and the
  DSP pipeline.
- `sensor/` — `SensorSource` interface plus one implementation per input:
  `CsvDatasetSource`, `UsbSerialSensorSource`, `BleSensorSource`. All are interchangeable behind the same interface,
  so `MainActivity` and the pipeline never need to know which is active.
- `dsp/PpgPipeline` — ties together `BiquadCascadeFilter` (band-pass),
  `RunningNormalizer`, `LmsMultichannelFilter` (accelerometer-referenced
  adaptive noise cancellation), and `HeartRateEstimator` (windowed FFT
  with second-harmonic correction and a reference-free SQI), mirroring
  the shape of the project's original MATLAB DSP pipeline but processing
  one live sample at a time.
- `history/` — Room database (`AppDatabase`, `ReadingEntity`,
  `SampleEntity`), `SessionRecorder` (batches samples off the producer
  thread onto a single consumer coroutine so recording never blocks
  sensor I/O or the UI), and `HistoryActivity`/`HistoryDetailActivity` for
  browsing past sessions.
- `dataset/` — reads `assets/datasets/datasets.json` (generated by
  `tools/prepare_datasets.py`) to populate the bundled dataset picker.
- `ui/WaveformView` — the live scrolling PPG waveform chart.

## Export format (raw samples)

**Export** (History → a reading → Export, or long-press in the list) saves
the reading's **raw samples as received** — before dropout filling, not
BPM/SpO2 — as one CSV, e.g. `Reading_12_20260928_1432_raw.csv`:

```
time,ir,red,accX,accY,accZ[,green]
0.000,115754,84194,-8.1429,-1.8161,5.8215
0.040,115666,84120,-8.2107,-1.803,5.8005
```

| Column | Meaning |
|---|---|
| `time` | seconds from the first sample, 3 decimals: the file's own time column (Dataset/File), the ESP32's clock (BLE) or the phone's arrival time (USB). Readings from before v3 use sample index ÷ rate |
| `ir`, `red` | raw ADC counts (integers) |
| `accX`, `accY`, `accZ` | accelerometer as received (m/s² for the rig) |
| `green` | only when the reading has green data — appended last |

- Header row, `,` separator, `.` decimal point in every locale.
- Empty cell = no value: a channel the source never had, an unreadable
  accelerometer sample (firmware `nan`), or older readings that stored
  only the accelerometer magnitude.
- Slots where nothing arrived (a gap) are not written, so `time` jumps
  there; uploading the file again (File source) re-detects the gap.
- Same layout as `walk_clean.csv`, `class_1_clean.csv` and
  `assets/datasets/hw_*.csv`; opens in Excel and loads in the MATLAB
  project's `load_dataset.m` unchanged (checked: fs = 25 Hz, and
  `select_best_ppg_channel.m` picks `ir`).
- Rows are streamed from the database in chunks off the main thread, so
  a 12-hour reading exports without loading it into memory.

## Hardware link

Two contracts document how the app talks to the ESP32 rig:

- **USB serial** (`USB_SERIAL_CONTRACT.md`, project root) — the active
  path: 115200 baud 8N1, one `ir,red,accX,accY,accZ` CSV line per sample
  at 25 Hz, auto-detected via `usb-serial-for-android`.
- **BLE** (`BleSensorSource.kt`'s header) — kept as reference/fallback
  code, using Nordic UART Service UUIDs; not yet wired against real
  firmware.

Both contracts are explicitly marked as best-effort assumptions pending
confirmation from whoever owns the ESP32 firmware — see each file's
"what's not decided yet" notes.

## Requirements

- Android Studio, min SDK 26, target/compile SDK 37.
- For the ESP32 (USB) source: a USB-OTG-capable phone and a cable to the
  sensor rig. No special permission grant needed beyond Android's own
  USB device-access dialog.
- For the ESP32 (BLE) source: Bluetooth runtime permissions are requested
  at launch time (`BLUETOOTH_SCAN`/`BLUETOOTH_CONNECT` on Android 12+,
  location on older versions).
